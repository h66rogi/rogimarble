# 게임 규칙·보드 설정 편집 UX

2026-09-21. 기존 저장·검증·게시 API 및 게임 계약을 유지하면서 설정 화면을 다시 구성했다.
일반 콘솔의 표현은 [공통 디자인 시스템](console-design-system.md)을 따른다.

## 기존 화면에서 바꾼 점

기존 화면은 후원 규칙, 아이템, 26개 칸, 방송 배치를 한 페이지의 긴 폼에 이어 붙였다.
운영자는 칸 ID로 대상을 찾고 실제 판을 보지 못한 채 입력해야 했다. 첫 번째 도착 효과만
편집할 수 있었고, 행·열 입력과 실제 재배치가 분리되어 잠시 모순되는 판을 만들 수 있었다.

상단 `게임 규칙`에는 후원 규칙·아이템을, `보드 설정`에는 게임판·방송 테마·배치·말 디자인을 둔다.
말 디자인은 선택 즉시 방송 화면에 반영한다. 현재 말 위치 보정은 진행 중인 게임의 조작이므로 홈에 둔다.
칸별 도착·통과 동작은 게임판 버전과 함께 저장되므로 게임판 편집 안에서 유지한다.
각 상단 탭은 자신의 첫 내부 메뉴를 연다. 방문한 설정 화면의 컴포넌트는 상단·내부 탭을 옮겨도 유지하며, 저장하지 않은 변경은 내부 탭과 하단에 표시한다.
내부 메뉴는 `meloming-front`의 `PillTabs` 모양을 따른다. 활성 버튼은 기본 색, 나머지는 외곽선과 둥근 모서리로 표시한다. 원본 `src/shared/components/ui/pill-tabs.tsx` (`f8907f37e73d0b760eac3c5af2beb48714331c83`)를 참고해 주루마블 공유 Button 기반으로 맞췄고, 탭 역할·방향키 이동·패널 연결을 유지한다.
방송 테마·배치는 공통 테마·글꼴 선택과 하나의 화면 미리보기를 나란히 놓고, 화면 기본값과 패널 문구를 아래에서 편집한다. 메뉴판·가격 패널은 하나의 편집 카드에서 전환한다. 이 값들은 초안 저장·검증·게시 후 적용된다. 파츠별 테마·글꼴·채팅 표시 옵션과 위치·크기는 `오버레이 설정`에서 즉시 저장하며, 파츠를 선택해 한 번에 하나만 편집한다. 따라서 기본값과 개별 덮어쓰기의 적용 시점을 화면에서 구분한다.
보드 설정 페이지의 기존 최대 폭 1600px과 중앙 정렬은 유지한다. 그 안에서 내부 편집기는 본문 폭을 그대로 사용한다. 방송 스타일 선택에는 더 넓은 열을, 게임판 미리보기와 화면 기본값에는 나머지 열을 배정한다. 위젯이 없는 초안에서도 선택한 기본 테마의 게임판을 보여주며, 전체 오버레이 미리보기는 위젯이 있을 때 펼쳐 볼 수 있다. 게임판 검사 패널도 넓은 화면에서 400~480px 폭을 확보한다.
각 설정 화면 상단에는 게시 후 실제 적용 시점을 안내하는 강조 알림을 둔다. 하단 저장 바는 본문 가장자리와 바닥에서 띄운 반투명 카드로 표시하고 뒤 콘텐츠를 흐리게 한다. 값이 바뀌면 경고색 표면·배지·아이콘과 큰 상태 문구로 미저장 상태를 드러낸다. 하단에는 설정 종류별 짧은 적용 시점 또는 방금 수행한 작업 결과를 표시한다. 게임판·후원 규칙·아이템·방송 스타일을 같은 일반 문구로 설명하지 않는다.
운영 메뉴로 이동했다가 돌아와도 편집 중 값이 남는다. 새로고침/닫기에는 브라우저의 미저장 알림을 사용한다.

## 게임판

- 판에서 칸을 선택하면 옆 패널에서 이름·도착 동작·꾸미기·통과 동작을 편집한다.
- 판은 실제 `BoardDefinition`의 배치·색상·모양·일러스트를 보여준다. 문구와 동작은 독립적이다.
- 전체 판 보기와 크게 보기, 칸 이름·번호 검색, 이전/다음 칸 선택, 이동 경로 표시를 제공한다.
- 순서 바꾸기 모드는 끌기 및 앞/뒤 버튼을 제공한다. stable ID와 해당 칸의 내용·동작이 함께 이동한다.
- 복수 효과와 실행 순서를 편집한다. 통과 효과에는 이동 경로를 변경할 수 없는 종류만 제시한다.
- 아이템·적립 항목·여행 목적지는 내부 ID 직접 입력 대신 표시 이름으로 선택한다.
- 편집 되돌리기/다시 실행은 로컬 초안에만 적용한다. 게임 결과를 되돌리는 명령이 아니다.
- 이동 미리보기는 지정 거리와 저장된 방향의 경로만 보여준다. 난수·효과 실행·후원·원장·명령 API를 호출하지 않는다.
- 좁은 화면에서는 전체 판을 축소해 보여주고 크게 볼 때 판 영역 안에서 스크롤한다. 칸을 선택하면 편집 패널로 이동하고 판으로 돌아갈 수 있다.

판 설정에는 제목, 출발점, 기본 방향, 주사위, 화면 크기, 외곽 행·열, 간격·여백,
적립 항목과 중앙 표시를 둔다. 자유 배치는 정규화 좌표를 유지하며 각 칸의 꾸미기에서 위치·크기를 조절한다.

외곽 크기는 입력하는 동안 현재 판을 바꾸지 않는다. 변경 전후 칸 수와 배치 미리보기를 확인한 뒤
한 번에 적용한다. 축소할 때는 제외할 칸을 직접 선택하고 사라지는 출발점·여행 목적지를 대신할
칸을 정한다. 중복 목적지는 정리하며, 남아 있는 칸의 ID와 효과를 보존한다.

## 후원 규칙

개수 → 동작을 카드 한 줄로 보여주며 하나를 선택해 편집한다. 이름, 정확한 후원 개수,
사용 여부, 동작별 값, 실드 정책을 설정한다. 복사는 새 ID와 중복 없는 개수를 부여하고 꺼진 상태로 시작한다.
삭제는 대상과 영향을 먼저 보여준다. 같은 개수 중복과 연속 주사위 비활성 상태를 표시한다.

후원 개수 확인은 기존 `resolveDonationTrigger` 코어를 사용한다. 배수·잔액 계산을 추가하지 않으며,
등록하지 않은 66개는 33개 규칙을 실행하지 않는다. 연속 주사위는 별도 허용과 개수별 횟수가 모두 필요하다.
이 확인 역시 실제 후원이나 게임 요청을 생성하지 않는다.

## 저장·게시

1. 초안 저장은 기존 create/update API를 사용하고 `expectedRevision`을 보낸다.
2. ‘검사하고 게시’는 변경된 초안을 저장한 뒤 서버에서 검사한다.
3. 검사에 성공하면 적용 내용·시점을 확인하는 창을 연다. ‘게시하기’를 눌러야 게시 API를 호출한다.
4. 게시에는 검사 응답의 revision을 사용한다. 이후 편집하면 다시 저장·검사해야 한다.

조회 실패는 오류·재시도로 보여주며 빈 초안으로 자동 대체하지 않는다. 저장 충돌은 입력을 유지하고
오류를 알린다. 기본 구성 가져오기는 교체 범위를 확인한 뒤 로컬 편집 값만 바꾼다.
아이템 편집은 저장된 초안/게시본이 없을 때 서버의 `effectiveDocument`를 읽어 기존 등록 항목을 보존한다.

게시된 게임판은 새 세션을 시작할 때 선택한다. 진행 중 세션의 상태를 바꾸는 명령은 이 편집기에서 실행하지 않는다.
기존 `apply_board_version`은 운영 화면과 서버의 별도 조건을 따른다.

## 검증 범위

`apps/web/test/configuration-editor-model.test.ts`는 순서 변경, 확장, 축소의 참조 복구, 화면 크기 분리,
불완전한 초안의 좌표 표시, 자유 배치에서의 경로 편집을 검사한다.
`apps/web/browser/configuration-editor.spec.ts`는 합성 API로 실제 폼 조작·탭 간 값 유지·revision·게시 확인·
효과 목록·정확 개수 확인·충돌·화면 폭을 검사한다.

합성 API 브라우저 검사는 실제 DB 저장, 후원 수집, 실방송 효과 실행 또는 OBS 검증을 대체하지 않는다.

2026-09-21 확인 결과: 원본 콘솔 틀을 보존하는 기준으로 복원한 뒤 웹 타입 검사와 프로덕션 빌드,
공통 디자인 검사(193개 소스 및 기존 46개 파일 기준선, 위반 0), 웹 단위 테스트 35개 통과.
코어 테스트 27개의 기존 통과 기록도 유지된다. 편집기 브라우저 시나리오 7개를 데스크톱/모바일에서
각각 실행한 14개와 공통 콘솔 시나리오 6개가 프로덕션 서버의 CSP를 유지한 상태에서 통과했다.
API는 합성 응답이며 운영 배포·DB·실방송 검증 결과를 의미하지 않는다.
