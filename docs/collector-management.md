# 방송·수집 관리 화면

운영 콘솔 상단의 **개발자도구** 링크 또는 `/collector`에서 확인한다.
로그인 세션과 해당 게임 채널의 조회 권한이 필요하다. 방송 조회 테스트는 운영 권한이 필요하다.
`수집 현황`에서는 연결·후원 처리·상세 진단을, `방송 테스트`에서는 다른 채널 방송 조회와
입장·채팅 수집 테스트를, `운영 기록`에서는 수동 조작·설정 변경 이력을 확인한다.
Pill Tabs를 전환해도 입력한 테스트 채널과 조회 결과는 유지된다.

## 확인할 수 있는 상태

- 주루마블 서버와 collector의 인증 연결, 운영 수집 채널, 방송 대기/연결/쿠키/저장 오류 상태
- collector의 마지막 입력 시각과 주루마블 DB의 마지막 후원·채팅 저장 시각
- 후원 처리 대기·검토 보류·실패·게임 반영·미적용 건수
- 같은 저장 세대에서 collector와 로컬 cursor의 차이, 채팅 스트림 요청/수신 상태
- 상세 진단의 cursor·저장 세대·복구 revision·수집 품질 사유

5초 자동 갱신을 끄거나 수동 새로고침할 수 있다. 화면이 숨겨져 있으면 자동 조회를 멈춘다.
collector 확인이 15초 이상 오래되거나 화면 갱신이 실패하면 최신 상태로 표시하지 않는다.
세션 만료 시 이전 상태를 지우고 로그인 링크를 보여 준다.

마지막 입력이 오래된 것만으로 장애를 판정하지 않는다. 조용한 방송과 방송 종료도 가능하다.
후원 건수는 현재 보관된 inbox 기준이며 결제 총액이 아니다. EC2 전체 컨테이너·백업 상태는 이 화면의 범위가 아니다.

## 다른 채널 방송 조회

SOOP 채널 ID를 입력하고 **방송 조회**를 누른다. URL 대신 영문·숫자·밑줄·하이픈 ID(최대 50자)를 받는다.
방송 여부와 제공된 제목·방송자·번호·확인 시각, SOOP 방송 링크를 표시한다.
쿠키 필요·접근 인증 필요·조회 실패를 방송 종료와 구분한다.

조회는 운영 수집 채널을 바꾸지 않는다. 테스트 대상의 채팅방에 입장하거나 후원·채팅을 게임에 연결하지 않는다.
연령제한 방송 확인에는 collector discover에 이미 주입된 쿠키를 사용한다.
SOOP 계정·쿠키·인증서·내부 주소·player ticket은 브라우저에 전달하지 않는다.

## 서버 계약

- `GET /v1/channels/:channelId/collector`: 세션 + 채널 조회 권한, `Cache-Control: no-store`.
- `POST /v1/channels/:channelId/collector/broadcast-check`: 세션 + CSRF + 채널 운영 권한.
  body는 `{ "targetChannelId": "fixture-channel" }` 형태다.
- 서버의 gRPC `CheckBroadcast` 요청은 고정된 운영 consumer/channel과 조회 대상 ID를 별도 필드로 전달한다.
  이 호출은 기존 후원 수신 루프와 다른 연결을 사용한다.
- collector query → discover 내부 토큰 → SOOP player API 순서로 확인한다. 운영 설정은
  [collector 방송 조회 문서](https://github.com/h66rogi/rogi-collector/blob/main/docs/broadcast-diagnostics.md)를 따른다.
- 같은 채널의 최근 10초 결과는 재사용하며 전체 초당 한 신규 조회·한 동시 요청 제한 초과는 HTTP 429다.
  수집기 미설정/연결 실패/기능 미배포는 503이며 내부 오류 문자열은 응답에 넣지 않는다.

## 검증 경계

합성 테스트는 세션·CSRF·역할·채널 범위 거부, proto의 운영/테스트 채널 분리,
collector의 실제 mTLS 소켓 권한 검사와 상태 분류를 다룬다. 브라우저에서는 결과 표시·모바일 화면과
테스트 조회 전후 운영 채널 유지를 확인한다. 실제 방송 체크는 플랫폼 조회 증거이며
실제 후원 수신→게임 실행 검증과 별도로 보고한다.

## 입장·채팅 수집 테스트

**입장·채팅 수집 테스트**에서 채널 ID를 입력하고 **입장·수집 시작**을 누른다.
실제 SOOP 채팅방 입장 ACK와 첫 일반 채팅 수신을 따로 확인하며, 수신 건수·최근 20개 채팅을 보여 준다.
화면에서 **테스트 종료**를 누를 수 있고, 창을 닫거나 접속이 끊겨도 시작 2분 후 서버가 자동 종료한다.
새로고침하면 서버의 현재 테스트를 다시 조회한다. 테스트는 같은 게임 채널 운영자들이 공유하는 슬롯 하나다.

기존 worker의 SOOP connector와 쿠키를 사용하지만 테스트 채팅·후원은 운영 DB/Redis나 게임에 전달하지 않는다.
샘플은 메모리에서만 최근 20개, 내용 1,000자·닉네임 80자로 제한하고 사용자 ID·원본 패킷은 반환하지 않는다.
마지막 결과는 종료 후 최대 5분 유지되며 새 테스트나 worker 재시작 시 대체/초기화된다.
채팅이 조용하면 입장 성공과 채팅 수신 0건을 그대로 보여 준다.

- `GET /v1/channels/:channelId/collector/chat-test`: 현재 테스트 상태와 샘플.
- `POST /v1/channels/:channelId/collector/chat-test`: `{ "targetChannelId": "fixture-channel", "sessionId": "11111111-2222-4333-8444-555555555555" }`.
- `POST /v1/channels/:channelId/collector/chat-test/:sessionId/stop`: 해당 테스트의 연결을 종료.

모든 경로는 로그인과 채널 운영 권한이 필요하고 POST는 CSRF를 검사한다. 조회 전용 계정은 샘플도 읽지 못한다.
UUID는 시작 재시도의 멱등 키다. 이전 테스트 ID의 종료 요청은 새 테스트를 끊지 않는다.
활성 테스트와 충돌하면 409, 시작 간격 5초 이내면 429, 만료/교체된 테스트 ID면 404다.
서버 RPC는 `StartChatTest`·`GetChatTest`·`StopChatTest`이며 query→worker 내부 진단 경로를 사용한다.
입장·수신 확인 성공은 테스트 커넥터 검증이며 실제 후원→게임 규칙 적용 검증과는 구분한다.
