# 독립 토큰 로그인과 collector 연결

2026-09-21 사용자 변경 요청에 따른 구현 계약이다. 로기챗 로그인 연결은 사용하지 않는다.

## 로그인

- 로그인 토큰은 `rma_` 접두어와 256비트 난수다. DB에는 해시만 보관한다.
- `/v1/auth/token`에 토큰을 제출하면 HttpOnly 세션과 CSRF를 발급한다. 원문을 URL이나 브라우저 저장소에 보관하지 않는다.
- 계정 화면에서 토큰을 추가 발급하고 회수한다. 기본 만료 30일, 최대 366일이다. 회수 시 연결 세션도 삭제한다.
- 최초 발급은 API의 `token:cli` 명령을 사용한다. 원격 로그에 원문을 남기지 않으려면 로컬에서 안전하게 생성한 토큰의 해시만 DB에 등록할 수도 있다. 출력은 권한이 제한된 파일로 전달하며 대화·배포 로그·소스에 넣지 않는다.
- 비밀번호 복구는 `PASSWORD_RECOVERY_ENABLED=true`가 명시된 관리자 계정만 허용한다. 운영 기본값은 꺼짐이다.

## 수집 연결

한 로컬 게임 채널과 한 collector 채널을 명시적으로 매핑한다. 실제 주소와 인증서는 private 호스트 설정에 둔다.
서버가 reader 인증서로 gRPC 상태·후원 목록·ACK와 채팅 스트림을 사용한다. 브라우저에 인증서를 전달하지 않는다.

1. collector의 범위, generation, recovery revision을 확인한다. 아직 로컬 소비 기록이 없는 최초 연결은 collector가 제공한 보존 시작 cursor에서 초기화한다. 기존 cursor가 있으면 자동으로 건너뛰지 않는다.
2. 저장된 cursor 이후 후원을 순서대로 조회한다. uint64 offset과 revision은 십진 문자열을 유지한다.
3. 같은 트랜잭션에서 inbox, 규칙 snapshot, 후원 내역과 연속 cursor를 저장한다.
4. DB 커밋 이후에만 collector ACK를 보낸다. 응답 유실 시 저장된 cursor로 재시도한다.
5. 별도 게임 처리에서 exact amount 규칙을 실행한다. 재접속 의심 관측과 지원하지 않는 후원 종류는 검토 상태로 보존한다.
6. 채팅 inbox와 cursor도 같은 트랜잭션에 저장한다. 과거 채팅을 새 목적지 요청에 적용하지 않도록 요청 시각·후원자·만료를 확인한다.
7. 세션 이전 관측을 새 세션에 자동 소급하지 않는다. 일시정지는 자동 이동을 대기시키고 미션·아이템 처리는 분리한다.

게임 결과는 서버 명령·원장·outbox로 저장하며 `donation` 출처와 inbox 참조를 남긴다.
수동 운영 명령은 계속 `operator` 출처를 사용한다. 콘솔과 OBS는 저장된 이동 결과를 재생한다.
보존 범위 만료나 generation/recovery 변경을 발견하면 자동으로 최신 offset으로 넘어가지 않고 복구 필요 상태를 표시한다.
운영 reader 인증서에는 복구 관리 권한이 없으므로 복구 권한을 별도로 준비한 운영 절차가 필요하다.

## 배포와 검증의 경계

API 프로세스가 수집 루프를 실행한다. 수집 연결 실패는 API와 수동 조작을 중지하지 않는다.
한 호스트의 API 인스턴스 간 후원 조회를 advisory lock으로 직렬화하고 수락/처리는 DB 제약으로 중복을 방지한다.
운영 인증서는 root 소유 원본에서 API용 tmpfs 디렉터리로 준비하고 디렉터리 전체를 읽기 전용으로 mount한다.
부트 시 복원, CA/SAN/keypair/만료 검사와 이전 mount 세대 보존은 배포 helper가 담당한다.

소비 계약 반입 범위는 [collector protobuf manifest](source-imports/collector-contract.json)의 공개 proto 1개다.
collector의 private 운영 설정, 플랫폼 계정, 원본 저장소의 전체 코드·이력을 가져오지 않는다.
합성 DB/gRPC 검사와 실제 방송 수신은 구분한다. 방송 대기 상태에서의 연결 성공을 실제 후원 게임 검증 완료로 표현하지 않는다.

## 운영 화면과 테스트 조회

콘솔의 `/collector` 화면에서 인증 연결·마지막 입력·후원 처리 건수·수신 지연과 복구 정보를 확인한다.
운영 권한 사용자는 다른 SOOP 채널도 조회할 수 있다. `CheckBroadcast`는 기존 consumer/channel의
인증 범위를 유지하고 조회할 ID를 별도로 전달한다. 테스트 채널의 수집 구독이나 게임 입력을 만들지 않는다.
자세한 사용법·권한·실패 상태는 [방송·수집 관리](collector-management.md)를 따른다.
