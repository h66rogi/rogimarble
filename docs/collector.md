# 수집기 연결과 진단

[rogi-collector](https://github.com/h66rogi/rogi-collector)는 SOOP 연결을 담당하고 Rogimarble API와 인증된 내부 gRPC로 통신합니다. 게임 채널과 수집 채널의 연결은 서버 설정으로 관리합니다. 수집 이벤트는 저장과 중복 확인을 거쳐 후원 규칙에 전달합니다.

운영 콘솔의 **개발자도구**에는 collector 연결, 방송 상태, 후원·채팅 수신 시각, 후원 처리 건수와 오류 분류가 표시됩니다. 화면의 마지막 입력 시각은 방송이 조용한 경우에도 오래될 수 있으므로 연결 상태와 함께 판단합니다. 운영 기록과 후원 처리 상세에서 원인 이벤트와 결과를 확인합니다.

## 방송 조회와 채팅 테스트

다른 SOOP 채널의 방송 조회는 운영 채널의 수집 설정을 바꾸지 않습니다. 입장·채팅 수집 테스트는 별도 세션으로 실행하고, 게임 후원과 채팅 내역에 테스트 메시지를 넣지 않습니다. 화면에서 테스트를 종료할 수 있으며 연결이 끊어져도 제한 시간 뒤 자동 종료됩니다. 채팅이 없는 방송에서는 입장 성공과 수신 0건을 각각 표시합니다.

관련 HTTP 경로는 `apps/api/src/collector.controller.ts`, gRPC 메시지는 `apps/api/proto/collector.proto`에 정의되어 있습니다. SOOP 연결과 collector 운영 계약은 수집기 저장소의 문서를 참고하세요.

## 후원 처리 확인

후원은 원천 이벤트 식별자와 채널 기준으로 중복을 확인한 뒤 inbox에 저장합니다. 규칙에 맞지 않는 개수도 후원 내역에 남기며 게임 명령을 생성하지 않습니다. 일치한 규칙과 적용된 설정 버전, 처리 결과를 후원 상세에서 확인합니다. 운영자 수동 명령은 별도 기록이므로 후원 통계에 합산하지 않습니다.

collector와 API의 저장 세대 또는 cursor가 어긋나면 연결 상태와 진단 필드를 함께 확인합니다. 재연결 뒤에는 이미 처리한 후원을 새 게임 결과로 재생하지 않도록 서버의 식별자와 저장 상태를 사용합니다. collector 상태 API가 실패할 때 콘솔은 마지막 성공값을 최신 상태로 표시하지 않습니다.

방송 조회 요청에는 SOOP 채널 ID를 사용합니다. 같은 대상의 짧은 간격 조회는 캐시를 사용하고, 과도한 요청은 제한합니다. 조회 결과에 내부 collector 인증서, 플랫폼 쿠키와 원본 패킷을 포함하지 않습니다. 채팅 테스트 샘플은 테스트 화면에서만 표시합니다.
