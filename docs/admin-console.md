# 서비스 관리자 화면

`/admin/login`은 서비스 관리자 전용 로그인이고 `/admin`은 계정·채널·접근 권한 관리 화면이다.
스트리머의 게임 운영 화면과 구분한다. 사용자 요청에 따라 단순한 아이디·비밀번호 방식으로 제공하며,
로기챗 공유 로그인 설정과 독립적으로 사용할 수 있다.

## 관리 범위

- 관리자·운영자·조회 계정 생성, 역할 변경, 사용 중지, 비밀번호 재설정
- 방송 채널 생성·이름 수정, 채널별 관리·운영·조회 권한 부여와 회수
- 로기챗 계정의 `accountPartition`을 기존 계정에 명시적으로 연결·해제
- 작업자·대상·전후 값이 기록된 관리자 변경 이력 조회
- 현재 비밀번호 확인 후 본인의 비밀번호 변경과 로그아웃

로기챗 식별자 입력만으로 로그인 신원을 증명하거나 공유 쿠키를 발급하지 않는다.
일반 로그인에는 [공유 인증의 선행 조건](authentication.md)이 별도로 필요하다.
관리자 기능을 게임 규칙·보드 편집 전체 구현 완료로 취급하지 않는다.

## 최초 계정과 인증

최초 관리자는 기존 `packages/database/src/bootstrap-admin.ts`로 명시적으로 생성한다.
공개 기본 비밀번호나 누구나 사용할 수 있는 가입·bootstrap HTTP API는 제공하지 않는다.
생성 도구의 비밀번호 입력은 비공개 실행 환경에서 제공하며, 원문을 Git·SSM 명령문·로그·CI에 넣지 않는다.
배포 운영자는 생성된 접근 정보를 저장소 밖의 접근 제한 파일로 전달한다.

관리자 세션과 일반 사용자 세션은 쿠키명·DB 세션·검증 경로를 분리한다.
관리자 요청마다 현재 계정의 활성 상태와 관리자 역할을 확인하며, 쓰기는 CSRF와 정확한 Origin을 검증한다.
비밀번호와 세션 토큰 원문은 DB에 저장하지 않는다. 로그인 실패 횟수를 제한하고,
권한 회수·비밀번호 변경 후 세션 재사용을 차단한다.

관리자 자신의 비활성화·역할 강등과 마지막 활성 관리자의 제거를 거부한다.
경쟁 요청의 권한 검증과 감사 기록은 DB 트랜잭션 안에서 처리한다.

## 검증

API 통합 검사는 전용 PostgreSQL 환경에서 관리자 인증, CSRF, 일반 세션 격리,
계정·채널 권한 변경, 세션 폐기와 동시 변경을 확인한다. 개발 PC에서 Docker를 다시
시작하지 않고 CI에서 통합 검사를 수행한다. 실제 배포에서는 로그인·페이지 로딩·
권한 거부·세션 종료와 폰트 로드를 별도로 확인한다.
